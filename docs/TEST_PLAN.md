# quant-infra 测试计划

> 版本 v1.0 · 2026-10-13 · 上游：CONSTRAINTS.md（EN/AC/RC 约束）、MODULE_DESIGNS.md（各模块测试要点 = DoD 来源）
> 定位：测试策略 + 分层定义 + **当前里程碑的具体用例规格**（输入与期望值写死，可直接变断言）。后续里程碑开工时在 §8 追加该里程碑用例节。

---

## 1. 原则

1. **测试是验收的唯一证据**：模块 DoD = 测试要点全过（PR-02）；"代码写完了"不是完成，"TC 全绿"才是。
2. **不变量优先**：AC/RC 类约束（账本正确性、fail-closed、防未来函数）必须各有对应测试；功能测试证明"能跑"，不变量测试证明"不会错"。
3. **测试随码写**：覆盖率门槛（EN-05）在 CI 强制，"最后补测试"会被合入门禁拦住。
4. **flaky 测试按缺陷处理**：重跑通过不算过，必须查明根因（S3 级缺陷）。
5. **具体数字进用例**：所有数值断言写具体期望值（本文 §4 就是规格），禁止 `assert!(x > 0)` 式的弱断言。

## 2. 测试分层

| 层 | 内容 | 位置 | 工具 | 执行时机 | 准出 |
|---|---|---|---|---|---|
| L1 单元 | 类型语义、纯函数（费用/舍入/涨跌停/校验器） | 各 crate `#[cfg(test)]` | cargo test | 每次 PR | TC 全绿 |
| L2 property | 不变量类：状态机迁移矩阵、账本守恒、崩溃恢复一致性 | `crates/*/tests/` | proptest（M2 起） | 每次 PR | 无反例 |
| L3 集成 | 跨模块链路：风控链全链路、事件存储 append-only、对账流程 | `tests/` | cargo test + testcontainers（M5 定） | 相关里程碑 | 场景全过 |
| L4 对抗 | RISK_CONTROL §7 的 13 条误用/攻击场景 | 对抗测试集 | — | M6 验收 + 风控链变更回归 | 13/13 |
| L5 演示 | DEVELOPMENT_PLAN §9 验收场景 | 演示记录 | — | 里程碑出口（PR-05） | 留档 |

## 3. 覆盖率与度量

- 工具：cargo-llvm-cov，门槛脚本 `scripts/check_coverage.sh`（核心 crate ≥90%、全局 ≥70%，EN-05）。
- 核心 crate 名单随里程碑扩充：event-core/oms/accounting/risk 合入即加入 `CORE_CRATES`。
- 覆盖率是必要条件不是充分条件：覆盖率 90% 但没有不变量断言 = 不合格，review 检查断言强度。

### 4.2 涨跌停价格（TC-C4-01..06）——含规格修正记录

> **修正记录 2026-10-13**：原设计文档写"按 tick 向内取整"，核对交易所交易规则后修正为**四舍五入至最小价格变动单位**（沪深北交易所规则原文口径：涨跌幅价格=前收盘价×(1±涨跌幅)，计算结果四舍五入取至 tick；以交易所规则原文为准）。若沿用"向内取整"，交易所认定的涨停价会被平台误判为超价废单——这是写具体用例时暴露的规格错误。

## 5. 测试代码纪律

- 测试模块头部显式豁免 lint（EN-03 的测试例外是显式行为）：
  ```rust
  #[cfg(test)]
  mod tests {
      #![allow(clippy::unwrap_used, clippy::expect_used)]
      // TC-C7-01: 买入10万费用对账（CONSTRAINTS AC-02/EN-04）
  ```
- 每个测试注释首行写用例 ID + 断言的约束 ID；断言消息里带 ID 便于 CI 报错定位。
- 命名描述行为：`fee_sell_100k_totals_81_41` 而非 `test_fees_2`。

## 6. 缺陷分级（M0.5 建 GitHub issues 后生效）

| 级 | 定义 | 时限 |
|---|---|---|
| S1 | 账本/风控/合规约束相关错误 | 当日修，阻断一切其他合并 |
| S2 | 功能错误 | 当前任务内修完才可提交 |
| S3 | 测试设施/CI 问题 | 48h，期间该 job 的红视为阻断（不允许因设施问题降门槛） |
