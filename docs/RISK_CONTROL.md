# quant-infra 风控与合规体系详设

> 版本 v0.1 · 2026-10-13 · 上游：`ARCHITECTURE.md` §5.4/§7/§8 · 实现 crate：`risk`、`compliance`、`settlement`
> 本文 §3 的检查链规格 = M6 验收测试的直接依据；每个检查器一条规格 = 一个测试用例族。
> 监管参数（300 笔/秒、20000 笔/日、费率、时段）集中在 §8 参数表，改动必须走双人审批 + 审计。

## 1. 威胁模型（风控在防什么）

| # | 威胁源 | 典型事故 | 防线 |
|---|---|---|---|
| T1 | 策略代码 bug | 死循环下单、金额单位错（元/分）、方向反 | 事前链 R2–R7 + 策略级熔断 |
| T2 | 触发监管红线 | 申报速率达高频认定阈值（300/s、2万/日）→ 账户被重点监控/限制 | R5 限流器 + R8 撤单比 + 利用率预警 |
| T3 | 数据错误 | 停牌股可交易、复权错价、未来数据 | data-platform 质量门 + R2 静态校验 |
| T4 | 人为误操作 | Admin 误改限额、Trader 下错数量 | 双人审批 + 审计 + R7 异常价格防护 |
| T5 | 组件故障 | 风控/日历/网关 panic 或超时 | **fail-closed：一律 safe mode** |
| T6 | 账户级市场风险 | 策略回撤失控 | 事中监控：回撤/日亏熔断 + kill switch |
| T7 | 自成交 | 同账户对倒（违规行为） | R6 自成交防范 |
| T8 | 账本漂移 | 本地账本与券商实际不一致 | 三方对账 + 差异禁交易 |

设计立场：**风控不是功能，是订单路径的物理结构**。策略到网关只有一条路，路上有链，链默认断开。

## 2. 三道防线总览

```
事前(每一单)          事中(持续)                 事后(每日)
┌─────────────┐   ┌──────────────────┐   ┌────────────────────┐
│ R0–R8 检查链 │   │ 回撤/日亏熔断      │   │ 三方对账(订单/成交/  │
│ + 合规限流器  │ → │ 撤单比/速率监控    │ → │ 对账单) 差异→禁交易  │
│ + kill switch│   │ 网关心跳/数据新鲜度│   │ T+1 解冻 · 日终清算  │
└─────────────┘   └──────────────────┘   └────────────────────┘
        ↓ 异常                                ↓ 月度
   safe mode(拒新单)                    合规报表(报备证据)
```

## 3. 事前检查链规格（R0–R8，顺序不可变）

铁律：
1. **链序不可变**：便宜的检查在前（内存判断），贵的在后（查库）；顺序变更 = 架构变更，需评审。
2. **检查器无副作用**：只读判定，唯一副作用是 R5 的令牌扣除（且失败时回滚语义见 R5）。
3. **全量留痕**：无论通过与否，每条检查输出 `(check_id, pass/fail, reason_code, 耗时µs)` 入事件存储。
4. **fail-closed**：链自身 panic/超时(>10ms/条) = 整单拒绝 + 引擎 safe mode。
5. **一票否决**：R0–R8 全过才可能到网关；无任何旁路 API（pybind 面没有绕过入口，ARCHITECTURE §4 依赖铁律保证）。

| ID | 检查 | 规则 | 数据来源 | 失败动作 | 边界条件 |
|---|---|---|---|---|---|
| R0 | 开关与会话 | 平台/账户/策略三级 kill switch 任一触发→拒；当前时段允许该订单类型（盘后固定价单仅 AfterHoursFix 时段；集合竞价单仅竞价时段） | kill switch 独立存储(Redis+本地文件双写)；Session 状态机 | 拒单 reason=KILL_SWITCH/SESSION_FORBIDDEN；竞价单在连续时段→挂起隔夜队列(不静默丢弃) | 9:20–9:25 与 14:57–15:00 不可撤（撤单请求直接拒绝并留痕）；11:30–13:00 收到的单挂起到 13:00 |
| R1 | 授权绑定 | 策略已绑定该账户；用户角色对账户有交易权限；账户处于"已报备"状态（compliance 档案存在且非"需重新报告"） | platform RBAC + compliance 档案 | 拒单；未报备账户→引擎实盘模式拒绝启动（进都进不来） | 模拟盘豁免"已报备"检查，但明示标记 |
| R2 | 订单静态合法性 | 标的上市且非停牌；价格 tick 对齐（股票 0.01/基金 0.001）；数量符合板块规则（主板/创业板 100 整数倍；科创板 200 起可 +1；北交所 100 起可 +1）；限价在涨跌停内（含 ST ±10%、创/科 ±20%、北交所 ±30%、新股规则、可转债规则） | Instrument 主档（data-platform 维护，质量门保证） | 拒单 reason=STATIC_*；废单语义与交易所一致 | 涨跌停价=昨收×(1±limit)，按交易所规则**四舍五入**至 tick（2026-10-13 修正：原文"向内取整"与交易所规则不符，会把交易所认定的涨跌停价误判为废单，见 TEST_PLAN §4.2）；ST 状态变更日以交易所标志为准；卖出允许零股但须一次性全部申报 |
| R3 | 资金充足 | 买入：`可用资金 ≥ 数量×价格 + 全部买入费用估算`（用 §5.5 舍入表）；卖出：不占资金 | accounting 可用资金 | 拒单 | 费用估算用保守上界（佣金按费率上界）；部分成交后的资金再校验在回报处理时做，不在链上做 |
| R4 | 持仓可用量（T+1 核心） | 卖出：`available_qty ≥ qty`；available = total − 当日买入冻结 − 当日已卖在途 | accounting 仓位簿 | 拒单 reason=T_PLUS_ONE | **当日卖出回款当日可用**（可再买入）→ 卖出成交即时贷记可用资金，但股份冻结至次日；当日买入的股份 available=0，15:35 结算后次日 09:00 前解冻 |
| R5 | 合规限流（高频阈值守护） | 令牌桶：账户级默认 5 笔/秒（桶深 10）；日累计申报+撤单 ≤ 2000（config 硬顶=20000 监管值）；策略级子限额（默认 2 笔/秒） | compliance 计数器（Redis 原子操作 + 本地内存双层） | 拒单 reason=RATE_LIMIT（**这单不扣日额度**——先检查后扣减，失败路径零副作用） | 计数口径=申报+撤单合计（与监管口径一致）；跨日重置以 trade_date 为准；Redis 不可用→fail-closed |
| R6 | 自成交防范 | 同账户存在对手方向、价格可交叉的在途单 → 拒新单（模式可配：拒新单默认/撤旧单/仅告警） | oms 在途单簿 | 拒新单 reason=SELF_TRADE | "可交叉"定义：buy_limit ≥ sell_limit；集合竞价阶段豁免（交易所竞价撮合不构成自成交） |
| R7 | 异常价格防护 | 限价偏离最新价超过阈值（默认 ±3%，可配）→ 拒单或降级为告警+二次确认（可配） | 行情最新价 | 默认拒单 reason=PRICE_DEVIATION | 最新价缺失（停牌复牌瞬间）→ 放宽到涨跌停边界判断，不得因数据缺失直接放行（fail-closed 原则下用保守边界） |
| R8 | 撤单比监控 | 当日 撤单/申报 比例 > 50% 且撤单数 > 100 → 新订单告警级拦截（可配为仅告警）；对应监管"频繁瞬时撤单"关注口径 | compliance 计数器 | 告警；超限严重时可配置为拦截 | 口径与交易所监控指标对齐，参数集中在 §8 表 |

## 4. 熔断与 Kill Switch（三级，独立于业务路径）

| 级别 | 作用域 | 触发方式 | 生效语义 |
|---|---|---|---|
| L1 平台 | 全部实盘 | Admin 手动；或自动：平台级异常（对账差异未解决、事件存储写失败、日历缺失） | 拒所有新单，在途单按预案撤单 |
| L2 账户 | 单账户 | Trader 手动；或自动：账户日亏 > 阈值（默认 −3%）、账户回撤 > 阈值（默认 −5% 自高点）、R5/R8 严重超限、网关心跳丢失 > 30s | 该账户拒新单 + 通知 |
| L3 策略 | 单策略 | 自动：策略回撤 > 阈值（默认 −2%）、策略异常下单速率、策略进程 panic | 暂停策略（已提交单保留，由人工决定撤否） |

- 存储独立性：kill switch 状态存 Redis + 本地文件双写，R0 每单必读；**Redis 与文件不一致 → 按已触发处理**（保守取向）。
- 恢复流程：只能人工恢复；L1 恢复需 Admin + 另一 Admin 双人确认（双人规则），全程审计。
- 自动触发的阈值全部集中在 §8 参数表，默认值写死在代码常量里作为 config 上界。

## 5. 事中监控（引擎内实时，秒级）

| 监控项 | 指标 | 告警 | 自动动作 |
|---|---|---|---|
| 账户回撤/日亏 | 实时 PnL vs 基准 | 阈值 80% 预警 | 触顶 → L2 熔断 |
| 策略回撤 | 策略级 PnL | 阈值 80% 预警 | 触顶 → L3 熔断 |
| 申报速率 | 秒滑窗/日累计 vs 300、20000 | 50%/80%/95% 三级 | 95% → 账户进入只允许撤单模式 |
| 撤单比 | 当日比例 | >50% 告警 | 见 R8 |
| 网关心跳 | 心跳间隔 | >10s 告警 | >30s → L2 |
| 行情新鲜度 | 最新 bar 延迟 | >2×周期 告警 | 数据断供 → 冻结依赖该数据的新开仓（已有持仓保护单除外） |
| 订单延迟 | submit→ack P50/P99 | P99 > 5s 告警 | 无自动动作，人工研判 |

## 6. 事后：清算与对账（settlement 模块）

每日时间线（T 日）：

| 时刻 | 动作 |
|---|---|
| 08:30 | 盘前自检：日历/Instrument/kill switch 状态/限流器清零确认 |
| 09:00 | T−1 买入股份解冻（available 更新） |
| 09:15–15:30 | 交易时段（引擎路径） |
| 15:35 | 结算：当日买入全部冻结（T+1）、生成账户日终快照 |
| 16:00 | 拉取券商对账单（资金/持仓/成交三表） |
| 16:15 | **三方对账**：本地订单 ↔ 本地成交 ↔ 券商对账单逐笔匹配；资金/持仓余额核对 |
| 16:30 | 对账报告：精确一致→归档；有差异→**L1 熔断次日交易 + 差异工单**，人工解决后双人确认恢复 |

对账细则（严格性所在）：
- 逐笔匹配键：`client_order_id + 券商回报号`；数量、价格、费用三字段全等才算匹配（费用差异 > 1 分即差异）。
- 余额核对：现金（含费用科目拆分）、每只标的持仓数量；差异金额 > 0 即失败，无容差。
- **差异处理铁律：以券商为准修账，修账必须产生审计事件（原因/依据/操作人），修账前平台处于禁交易状态。**
- 月度合规报表：当月申报/撤单统计 vs 阈值利用率、费率执行情况、异常事件汇总——导出即报备/检查证据。

## 7. 对抗性测试清单（M6 验收 = 逐条变成测试用例）

| 场景 | 期望行为 |
|---|---|
| 策略循环提交 1000 单/秒 | R5 第 6 单/秒起拒绝；日计数只含成功通过的单；无 20000 可能性 |
| 卖出当日买入的股票 | R4 拒绝，reason=T_PLUS_ONE；账本 available 不变 |
| 挂买 100.01 再挂卖 100.01（同账户） | R6 拒新单（默认模式） |
| 对停牌股下单 | R2 拒绝（Instrument 状态=停牌） |
| 限价超涨跌停 0.01 元 | R2 拒绝；对 ST 用 ±10% 而非 ±5%（2026-07 新规回归用例） |
| 9:21 提交撤单 | 直接拒绝并留痕（不可撤窗口） |
| 风控链注入 panic | 整单拒绝 + safe mode + 告警；绝不放行 |
| Redis 不可用时限流器 | fail-closed：拒绝新单 |
| kill switch 文件与 Redis 状态冲突 | 按"已触发"处理 |
| 修账后直接恢复交易 | 不允许：必须双人确认，审计可查 |
| 回测中访问 `ctx.now()` 后的数据 | 数据 API 只返回 close_time ≤ now 的 bar；未来 bar 不可见（P5 用例） |
| 修改 config 中限流上限为 30000/日 | 配置校验拒绝：超过监管硬顶；尝试绕过 → 审计告警 |
| 券商对账单比本地多一笔成交 | 16:15 对账失败 → 次日禁交易 + 差异工单 |

## 8. 参数表（唯一事实源，双人审批变更）

```toml
[risk.rate_limit]          # R5：合规限流（config 硬顶=监管值，不可超）
per_second_default = 5     # 默认
per_second_hard_cap = 300  # = 高频认定阈值，config 超过即启动失败
per_day_default = 2000
per_day_hard_cap = 20000
burst = 10

[risk.circuit_breaker]
account_daily_loss_pct = 3.0
account_drawdown_pct = 5.0
strategy_drawdown_pct = 2.0
gateway_heartbeat_timeout_s = 30

[risk.price_deviation]     # R7
max_deviation_pct = 3.0
action = "reject"          # reject | warn

[risk.cancel_ratio]        # R8
alert_pct = 50
alert_min_cancels = 100
block_enabled = false      # 默认告警不拦截，开启属 L2 级变更

[compliance.reporting]     # R1：报备
require_profile_for_live = true
```

> 变更规则：任何值修改 = `change_id` 审计事件（谁/何时/旧值/新值/审批人）；硬顶类字段写入时校验，越顶配置启动即失败。

## 9. 与监管条款的对应（摘要，全表见 ARCHITECTURE §8）

程序化交易事前报告 → R1；高频认定阈值 → R5/R8 + 事中"申报速率"监控 + §6 月度报表；留痕 → 事件存储哈希链 + 本文所有 reason_code 留痕；外接新规熔断 → §4 三级 kill switch；频繁瞬时撤单监控 → R8。
